# Submitting Fearless to TechEmpower FrameworkBenchmarks

This is the checklist to get Fearless on the public TFB leaderboard. Until this PR lands, the project's "we hit Top 10" claim has no public proof.

## 0. What you're submitting

A new framework entry under `frameworks/TypeScript/fearless/` in the [TechEmpower/FrameworkBenchmarks](https://github.com/TechEmpower/FrameworkBenchmarks) repo. The entry contains:

- A `Dockerfile` that builds and runs the framework on the TFB toolset image
- A `benchmark_config.json` declaring the 4-6 endpoints we serve
- A `README.md` describing the framework, language, dependencies
- The framework source (or a thin shim that fetches the published package — they prefer the former)

## 1. Local validation against the TFB toolset

Before any PR, run the TFB harness locally to confirm the entry is structurally valid.

```bash
# Get the TFB repo (sibling of fearless)
cd ..
git clone https://github.com/TechEmpower/FrameworkBenchmarks
cd FrameworkBenchmarks

# Verify the toolset can introspect our framework declaration
./tfb --mode verify --test fearless

# Run it for real (this takes 10-30 minutes per test)
./tfb --mode benchmark --type plaintext --test fearless --duration 15
./tfb --mode benchmark --type json --test fearless --duration 15
./tfb --mode benchmark --type db --test fearless --duration 15
./tfb --mode benchmark --type query --test fearless --duration 15

# Results land in results/<timestamp>/results.json
```

If verify fails, the most common causes are:
- Missing or malformed `benchmark_config.json`
- Framework binds to wrong port (must be 8080)
- Postgres connection string differs from TFB's expected (see their `tfb_database` env)
- Container can't be killed cleanly (TFB sends SIGTERM, framework must shut down)

## 2. Files to commit upstream

In the TFB repo, create `frameworks/TypeScript/fearless/`:

```
frameworks/TypeScript/fearless/
├── Dockerfile                  # mirrors bench/techempower/fearless-rust-aot.dockerfile
├── benchmark_config.json       # mirrors our bench/techempower/benchmark_config.json
├── README.md                   # short framework intro
├── rust-core/                  # the Rust source (cargo build runs in Dockerfile)
├── packages/aot-analyzer/      # for fearless-build during the docker build
├── packages/aot-transpiler/
├── packages/aot-build/
├── scripts/fearless-build.mjs
├── examples/tfb/server.ts      # TFB-flavored entry app (4-6 routes mapped to TFB urls)
└── seed.sql                    # World + Fortune tables, TFB-canonical
```

The `Dockerfile` should:
1. Install Node + Bun
2. Run `node scripts/fearless-build.mjs examples/tfb/server.ts --no-cargo`
3. `cargo build --release --features io-uring,aot-handlers --manifest-path rust-core/Cargo.toml`
4. CMD that starts the rust-core binary AND (if Bun fallback is enabled) starts Bun in parallel

Use multi-stage build to keep the final image lean.

## 3. PR description template

Use this template (paste into the GitHub PR body):

```markdown
## Adds: TypeScript / Fearless

**Framework:** Fearless — a TypeScript microframework with a hybrid Rust + Bun runtime. TypeScript handlers compile to native Rust at build time (AOT) when they fit a documented subset; everything else falls back to Bun's native HTTP path.

**Repo:** https://github.com/rodrigooler/fearless

**Tests included:**
- [x] plaintext       — Rust-served, AOT-compiled response
- [x] json            — Rust-served, AOT-compiled response
- [x] db              — Bun + Postgres (typed handle in Phase 1; for now, raw pg client through Bun fallback)
- [x] query           — Bun + Postgres
- [ ] fortunes        — not yet (planned for Phase 1)
- [ ] update          — not yet (planned for Phase 1)
- [ ] cached-query    — not yet

**Two configurations:**
- `default` — full hybrid runtime, full TFB test suite
- `aot` — AOT-only, plaintext + json (clean comparison vs C++/Rust frameworks)

**Notes:**
- Requires kernel ≥ 5.19 (AcceptMulti) and ≥ 6.0 for the `setup_defer_taskrun` path.
- Container needs `--cap-add SYS_NICE` (for io_uring SQPOLL) and `--cap-add NET_ADMIN` (for SO_ATTACH_REUSEPORT_CBPF). Both are documented in our deploy guide.
- AOT handlers are static-analyzed at build time; CI only needs `cargo build`.

**Local results** (Mac OrbStack VM 10 vCPU, not Citrine; submitting for the real run):
- plaintext pipeline-32: 9.45M req/s
- json pipeline-32: 9.75M req/s
- non-pipelined c=64: 400-440k req/s for AOT routes

Looking forward to the Citrine numbers.
```

## 4. Common reviewer asks

The TFB maintainers ask consistent things. Have answers ready:

- **"Why language=TypeScript when most of the work is Rust?"** Because the developer writes TypeScript. The Rust code is generated by the framework at build time, not authored. The "language" field in TFB tracks what the developer writes, per their own glossary entry on language. Display name `fearless` makes the hybrid nature clear.
- **"Why two configurations?"** The default reflects realistic deployment (handlers + DB). The `aot` config measures the AOT-only Rust ceiling — the comparable case to may-minihttp / drogon / xitca-web, which is what Top 10 plaintext is fought over.
- **"What kernel features are required?"** kernel ≥ 6.0 for the optimal path, ≥ 5.19 for graceful fallback. TFB's reference Linux is ≥ 6.0 so this is fine.

## 5. After the PR merges

The first official benchmark run usually lands within 1-2 weeks (TFB has a queue). When results show up:

1. Update `benchmark.json` in the Fearless repo with the official `results.json` URL.
2. Update README "Performance" section with the real numbers.
3. Tweet / blog post linking to the public benchmark.
4. Open follow-up PRs for fortunes, update, cached-query as Phase 1 typed handles land.

## 6. Submission timing

TFB runs are queued; PRs typically wait 1-3 weeks for the first benchmark publish. Worth syncing the announcement with the publish event for maximum visibility.
